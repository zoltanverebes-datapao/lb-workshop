# S5: Serve frontend static build from backend at /app

Status: **IMPLEMENTED**

Inherits: `docs/conventions.md`, `docs/rubric-base.md`, `docs/glossary.md`

Depends on: S1 (FastAPI backend), S4 (frontend scaffolding with Vite build)

## Goal

When only the backend server is running (no separate frontend dev server), a
browser navigating to `{domain}/app` sees the fully rendered React application.
Asset paths resolve correctly, client-side routing works for any `/app/*` path,
and existing API routes under `/api/*` continue to function without interference.

## Scope

In:
- `backend/app/main.py` -- mount static files and SPA fallback
- `frontend/vite.config.ts` -- set `base: '/app/'`
- `frontend/index.html` -- asset src paths may need updating for the new base

Out:
- Client-side routing library (React Router) -- owner: first multi-page item
- Dockerfile or production deployment configuration
- Changes to `scripts/verify.sh`
- Changes to `playwright.config.ts`
- New backend dependencies beyond what FastAPI already provides (`starlette` ships `StaticFiles`)

## Interface contract

### Static file mount

The backend serves the contents of `frontend/dist/` under the URL prefix `/app`.
The mount uses FastAPI/Starlette's `StaticFiles` with `html=True`.

### SPA fallback

Any request to `/app` or `/app/{path:path}` that does not match a static file
in `frontend/dist/` returns `frontend/dist/index.html` with status 200 and
content type `text/html`. This enables client-side routing for deep links such
as `/app/products/123`.

### Vite base path

`frontend/vite.config.ts` sets `base: '/app/'` so that built assets (JS, CSS)
use `/app/assets/...` paths in the generated HTML.

### Route precedence

API routes (`/api/*`) are registered via `include_router` before the static
mount, so they take precedence. A request to `/api/health` returns the JSON
health response, not `index.html`.

### Build prerequisite

The frontend must be built (`cd frontend && npm run build`) before the backend
can serve it. If `frontend/dist/` does not exist at startup, the backend may
fail to start or may start without the mount -- the spec does not prescribe
graceful degradation, but the mount must work when the directory exists.

### No fixtures

This item has no database interaction and no test fixtures.

## Notes

- `StaticFiles` from `starlette.staticfiles` is already available as a
  transitive dependency of FastAPI. No new package install is needed.

- The `html=True` parameter on `StaticFiles` makes it serve `index.html` for
  directory requests and as a fallback for missing files, which provides the
  SPA routing behaviour. If `html=True` alone does not cover all SPA fallback
  cases (e.g. paths with dots that look like file extensions), the builder may
  need a custom fallback route or middleware. The rubric (C3) tests a deep
  nested path to verify.

- The `frontend/dist/` directory is already gitignored (S4, C12). The builder
  must not commit built assets.

- Standing rubric criteria S2/S3/S4 (migration-related) do not apply to this
  item since no database changes are made. S5 (API types in sync) also does not
  apply since no new API routes are added.

- The `index.html` source file at `frontend/index.html` references
  `src="/src/main.tsx"`. After `vite build` with `base: '/app/'`, the built
  output will have transformed paths like `/app/assets/...`. The source
  `index.html` script src does not need to change -- Vite handles the
  transformation at build time.
