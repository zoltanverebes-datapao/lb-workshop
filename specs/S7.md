# S7: Construct DATABASE_URL from PG* env vars in start.sh

Status: **IN PROGRESS**

Inherits: `docs/conventions.md`, `docs/rubric-base.md`, `docs/glossary.md`

Depends on: S6 (IMPLEMENTED)

## Goal

When the application is deployed as a Databricks App, the startup script
constructs `DATABASE_URL` from the individual PG* environment variables that
Databricks provides (`PGHOST`, `PGPORT`, `PGSSLMODE`, `PGDATABASE`, `PGUSER`).
The backend application code continues to read `DATABASE_URL` unchanged. Local
testing is unaffected because tests set `DATABASE_URL` directly and never
execute `start.sh`.

Two bugs in the current `start.sh` are also fixed: the `--host` flag uses the
literal string `"PGHOST"` instead of `0.0.0.0`, and the `--port` flag reads
`$PGPORT` instead of `$DATABRICKS_APP_PORT`.

## Interface contract

### `scripts/start.sh` behaviour

The script adds a `DATABASE_URL` construction block **before** the dependency
install steps. The logic is:

1. If `DATABASE_URL` is already set and non-empty, use it as-is (allows local
   override and alternative deployments).
2. Otherwise, construct it from PG* env vars:
   ```
   DATABASE_URL="postgresql://${PGUSER}@${PGHOST}:${PGPORT}/${PGDATABASE}?sslmode=${PGSSLMODE}"
   ```
3. Export `DATABASE_URL` so child processes (uvicorn via `exec`) inherit it.

### Host and port fix

The `uvicorn` invocation must use:
- `--host 0.0.0.0` (listen on all interfaces, not the literal string `"PGHOST"`)
- `--port "$DATABRICKS_APP_PORT"` (the Databricks-provided port, not `$PGPORT`)

### Connection string format

`postgresql://${PGUSER}@${PGHOST}:${PGPORT}/${PGDATABASE}?sslmode=${PGSSLMODE}`

No password component. Databricks uses IAM-style authentication; the PG*
variables do not include `PGPASSWORD`.

### No fixtures, no routes, no test IDs

This item adds no API routes, no database changes, and no UI elements.

## Notes

- Standing rubric criteria S2/S3/S4 (migration-related) do not apply to this
  item since no database changes are made. S5 (API types in sync) also does not
  apply since no new API routes are added. S9 (contract tests frozen) applies
  trivially -- no contract tests exist for this item.

- The current `start.sh` has two bugs introduced in S6: `--host "PGHOST"`
  (literal string, not a variable or the correct value) and `--port "$PGPORT"`
  (wrong variable -- should be `$DATABRICKS_APP_PORT`). Both are corrected in
  this item.

- `export` in a bash script makes the variable available to child processes.
  Since uvicorn is launched via `exec`, it replaces the shell process and
  inherits the exported environment, making `DATABASE_URL` visible to the
  Python application.
