# S7: Databricks Lakebase connection with OAuth token auth

Status: **IMPLEMENTED**

Inherits: `docs/conventions.md`, `docs/rubric-base.md`, `docs/glossary.md`

Depends on: S6 (IMPLEMENTED)

## Goal

When the application is deployed as a Databricks App, it connects to the
Lakebase PostgreSQL endpoint using per-connection OAuth token authentication
via the Databricks SDK. The backend detects the Databricks environment by
the absence of `DATABASE_URL` and the presence of `PGHOST`, constructs a
keyword-format `conninfo` from PG* env vars, and uses a custom connection
class that fetches a fresh token for every new connection. Local development
and testing remain unaffected -- when `DATABASE_URL` is set, the app uses it
directly without the Databricks SDK.

The current `start.sh` constructs a `DATABASE_URL` from PG* vars at the
shell level. That block is removed; connection logic now lives entirely in
Python.

## Scope

In:
- `backend/app/db.py` -- dual-path pool creation with OAuthConnection
- `backend/app/main.py` -- Yoyo migration connection string
- `backend/pyproject.toml` -- add `databricks-sdk` dependency
- `scripts/start.sh` -- remove DATABASE_URL construction block

Out:
- `app.yaml` -- no changes; `ENDPOINT_NAME` is configured in the Databricks App UI, not committed
- Backend scripts (`backend/scripts/init_db.py`, `backend/scripts/truncate_db.py`) -- local-only, always have `DATABASE_URL`
- Test configuration (`playwright.config.ts`, `backend/tests/conftest.py`) -- tests set `DATABASE_URL` directly
- `scripts/verify.sh` -- no changes
- Frontend code

## Interface contract

### Environment detection and pool creation (`backend/app/db.py`)

Three paths, checked in order:

**Path A -- Local/test (`DATABASE_URL` is set):**
- Pool `conninfo` is `DATABASE_URL` value, as today.
- Default `connection_class` (no `OAuthConnection`).
- `databricks.sdk` is never imported.

**Path B -- Databricks (`DATABASE_URL` is NOT set, `PGHOST` IS set):**
- Read `PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER`, `PGSSLMODE` from env.
- Read `ENDPOINT_NAME` from env.
- Construct `conninfo` in keyword format:
  `dbname={PGDATABASE} user={PGUSER} host={PGHOST} port={PGPORT} sslmode={PGSSLMODE}`
- Define an async connection subclass (or use `AsyncConnectionPool`'s
  `configure` callback) that calls
  `WorkspaceClient().postgres.generate_database_credential(endpoint=ENDPOINT_NAME)`
  to set the password on each new connection. The Databricks tutorial uses a
  sync `psycopg.Connection` subclass overriding `connect()`. Our pool is
  async (`AsyncConnectionPool`), so the builder must adapt -- either by
  subclassing `psycopg.AsyncConnection` or by using the pool's `configure`
  callback. Both are acceptable as long as a fresh token is fetched per
  connection.
- Pass the custom class or callback to `AsyncConnectionPool`.

**Path C -- Neither `DATABASE_URL` nor `PGHOST` is set:**
- Raise `RuntimeError` (same behaviour as today).

The module-level guard changes from checking only `DATABASE_URL` to checking
that *either* `DATABASE_URL` or `PGHOST` is set.

The pool is still created with `open=False` and opened in the lifespan.

### Exported helper for Yoyo (`backend/app/db.py`)

Export a function (e.g. `get_yoyo_url() -> str`) that returns a synchronous
Yoyo-compatible URL:

- Path A: take `DATABASE_URL`, replace `postgresql://` with
  `postgresql+psycopg://`.
- Path B: fetch a one-time token via
  `WorkspaceClient().postgres.generate_database_credential(endpoint=ENDPOINT_NAME)`,
  construct `postgresql+psycopg://{PGUSER}:{token}@{PGHOST}:{PGPORT}/{PGDATABASE}?sslmode={PGSSLMODE}`.

This keeps the token-fetching logic consolidated in `db.py`.

### Yoyo migrations (`backend/app/main.py`)

The lifespan function calls the `get_yoyo_url()` helper from `app.db`
instead of reading `os.environ["DATABASE_URL"]` and doing the scheme rewrite
inline. The `os.environ["DATABASE_URL"]` reference is removed from
`main.py`.

### `scripts/start.sh`

Remove the `DATABASE_URL` construction block (current lines 4-7 that build
`DATABASE_URL` from PG* vars and export it). The script keeps:
- `#!/usr/bin/env bash`
- `set -e`
- Frontend `npm install` + `npm run build`
- Backend `uv sync`
- `exec uv run uvicorn app.main:app --host 0.0.0.0 --port "$DATABRICKS_APP_PORT"`

The script must not mention `DATABASE_URL` at all.

### `backend/pyproject.toml`

Add `databricks-sdk` to the `dependencies` list.

### Deferred import rule

The `databricks.sdk` import must be inside the function or branch that needs
it (Path B only), never at module level. Local environments must never
trigger a `databricks` import.

### Local testing guarantee

When `DATABASE_URL` is set (as in `playwright.config.ts`, `conftest.py`, and
manual dev), the code takes Path A -- identical to current behaviour. No
test changes are needed.

### No fixtures, no routes, no test IDs

This item adds no API routes, no database changes, and no UI elements.

## Notes

- Standing rubric criteria S2/S3/S4 (migration-related) do not apply to this
  item since no database changes are made. S5 (API types in sync) also does
  not apply since no new API routes are added. S9 (contract tests frozen)
  applies trivially -- no contract tests exist for this item.

- The Databricks SDK auto-configures from `DATABRICKS_*` env vars present in
  the app runtime. No explicit configuration beyond `ENDPOINT_NAME` is
  needed in code.

- The tutorial example uses sync `psycopg.Connection` and `ConnectionPool`.
  Our codebase uses `psycopg.AsyncConnection` and `AsyncConnectionPool`.
  The builder must verify that the chosen approach (subclass or callback)
  works with the async pool. The `configure` callback on `AsyncConnectionPool`
  receives each connection after creation and can set the password; this may
  be simpler than subclassing `AsyncConnection`.

- OAuth tokens expire. Fetching a fresh token per connection (via the custom
  connection class or callback) is the correct pattern -- it avoids stale
  tokens when the pool recycles connections. This matches the Databricks
  tutorial's approach.

- `backend/scripts/init_db.py` and `truncate_db.py` are local-only tools
  that read `DATABASE_URL` directly. They are not modified.

- The `ENDPOINT_NAME` env var format is:
  `projects/<project-id>/branches/<branch-id>/endpoints/<endpoint-id>`.
  It is configured in the Databricks App UI, not in `app.yaml`.

- The keyword-format conninfo (`dbname=... user=... host=...`) is required
  for Lakebase connections. URL-format conninfo does not work because the
  password (OAuth token) is set per-connection, not in the conninfo string.
