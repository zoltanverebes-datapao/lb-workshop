# S3: Initial Domain Implementation

Inherits: `docs/conventions.md`, `docs/rubric-base.md`, `docs/glossary.md`

Depends on: S2 (database connection and migration infrastructure)

Domain layer setup: Product and StockLevel entities with database migrations and repository layer.

## Summary

Implement the foundational data model with two entities:
- **Product**: catalog entries with id, name, and description
- **StockLevel**: quantity tracking linked to products with unit of measurement

This includes:
1. Yoyo database migrations to create `products` and `stock_levels` tables
2. Pydantic DTO dataclasses for API serialization (camelCase JSON aliases)
3. Repository layer (ProductRepository, StockLevelRepository) with CRUD operations using raw SQL

No ORM. Repositories execute parameterized SQL via the psycopg `AsyncConnection`
provided by S2's `get_conn` dependency.

## Scope

### In scope
- Yoyo migration script(s) in `backend/migrations/` to create both tables with foreign key and index
- Create `products` table (columns per glossary, `snake_case` in DB)
- Create `stock_levels` table (columns per glossary, `snake_case` in DB)
- Pydantic DTOs in `backend/app/schemas/`
- Repository classes in `backend/app/repositories/` with CRUD operations using raw SQL
- Foreign key constraint from `stock_levels.product_id` to `products.id`
- Index on `stock_levels.product_id`

### Out of scope
- API endpoints (handled by a future item)
- Frontend components
- Authentication/authorization

## Database Schema

All column names are `snake_case` per conventions. Pydantic DTOs alias to `camelCase` for JSON.

### products table
- `id`: UUID, primary key, default `gen_random_uuid()`
- `name`: VARCHAR, not null
- `description`: TEXT, nullable
- `created_at`: TIMESTAMPTZ, not null, default `now()`
- `updated_at`: TIMESTAMPTZ, not null, default `now()`

### stock_levels table
- `id`: UUID, primary key, default `gen_random_uuid()`
- `product_id`: UUID, not null, foreign key to `products.id`, indexed
- `quantity`: INTEGER, not null
- `measure`: VARCHAR, not null, check constraint: one of `pieces`, `kilogram`, `gram`, `litre`
- `created_at`: TIMESTAMPTZ, not null, default `now()`
- `updated_at`: TIMESTAMPTZ, not null, default `now()`

## Implementation Details

### Yoyo Migrations
Create migration file(s) in `backend/migrations/` with SQL statements to:
- Create `products` table with columns and constraints
- Create `stock_levels` table with columns, foreign key to products, and check constraint on `measure`
- Each migration must be reversible (rollback drops the tables)

### Pydantic DTOs
Located in `backend/app/schemas/product.py` and `backend/app/schemas/stock_level.py`:
- `ProductDTO`: all fields, aliases `created_at` -> `createdAt`, `updated_at` -> `updatedAt`
- `CreateProductInput`: `name` (required), `description` (optional)
- `StockLevelDTO`: all fields, aliases `product_id` -> `productId`, etc.
- `CreateStockLevelInput`: `productId` (required), `quantity` (required), `measure` (required)

### Repository Layer
Located in `backend/app/repositories/`:
- `ProductRepository`: async methods `create()`, `get_by_id()`, `list_all()`, `update()`, `delete()` using raw SQL
- `StockLevelRepository`: async methods `create()`, `get_by_id()`, `list_by_product()`, `update()`, `delete()` using raw SQL
- Repositories accept a psycopg `AsyncConnection` from S2's `get_conn` dependency
- Methods use parameterized queries (`%s` placeholders, prevent SQL injection)
- Query results are mapped to Pydantic DTOs via `row_factory` or manual mapping

### Dependencies
No new dependencies required. Pydantic is already available via FastAPI (S1).
Database access via psycopg `AsyncConnection` (S2).
