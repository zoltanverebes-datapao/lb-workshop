# S6: Databricks App deployment configuration

Status: **IN PROGRESS**

Inherits: `docs/conventions.md`, `docs/rubric-base.md`, `docs/glossary.md`

Depends on: S5 (backend serves frontend static build at /app)

## Goal

When Databricks deploys this application from the `main` branch, it finds an
`app.yaml` at the project root that points to a startup script. That script
installs frontend and backend dependencies, builds the frontend, and starts the
backend server on the port Databricks provides. No manual steps beyond
configuring the Databricks App resource itself.

## Scope

In:
- `app.yaml` (new file, project root)
- `scripts/start.sh` (new file, startup script)

Out:
- Databricks resource bindings, secrets, or SQL Warehouse configuration
- CI/CD pipeline configuration
- Database connection / `DATABASE_URL` management (configured in Databricks UI)
- Changes to backend or frontend application code
- Dockerfile or container-based deployment
- Changes to `scripts/verify.sh`

## Interface contract

### `app.yaml` (project root)

```yaml
command: ['bash', 'scripts/start.sh']
```

No `env` block. Environment variables (`DATABASE_URL`, `DATABRICKS_APP_PORT`)
are provided by the Databricks runtime or configured in the Databricks App UI.

### `scripts/start.sh`

A bash script that performs the following steps in order:

1. **Install frontend dependencies**: `cd frontend && npm install`
2. **Build frontend**: `cd frontend && npm run build`
3. **Install backend dependencies**: `cd backend && uv sync`
4. **Start backend server**: `uvicorn app.main:app --host 0.0.0.0 --port $DATABRICKS_APP_PORT`
   (run from within the `backend/` directory so Python imports resolve)

The script must:
- Use `#!/usr/bin/env bash`
- Use `set -e` so any failing step aborts the deploy
- Be executable (`chmod +x`)
- Reference `DATABRICKS_APP_PORT` for the listen port (not a hardcoded value)
- Run `uvicorn` via `uv run` (to use the backend's virtual environment) as the
  final command (via `exec` so the server process replaces the shell and receives
  signals correctly)

### No fixtures, no routes, no test IDs

This item adds no API routes, no database changes, and no UI elements.

## Rubric

Standing criteria in `docs/rubric-base.md` also apply. Number from C1.

- C1: `app.yaml` exists at the project root, is valid YAML, and its `command`
      field equals `['bash', 'scripts/start.sh']`.
      -- verified by: `python3 -c "import yaml, sys; d=yaml.safe_load(open('app.yaml')); assert d['command']==['bash','scripts/start.sh'], f'command is {d[\"command\"]}'; print('OK')"`

- C2: `scripts/start.sh` exists and is executable.
      -- verified by: `test -x scripts/start.sh && echo OK`

- C3: `scripts/start.sh` starts with a bash shebang line (`#!/usr/bin/env bash`).
      -- verified by: `head -1 scripts/start.sh | grep -qx '#!/usr/bin/env bash' && echo OK`

- C4: The script contains `set -e` (fail-fast on errors).
      -- verified by: `grep -q 'set -e' scripts/start.sh && echo OK`

- C5: The script installs frontend dependencies (`npm install` or `npm ci` in
      the `frontend/` directory).
      -- verified by: `grep -qE 'npm (install|ci)' scripts/start.sh && echo OK`

- C6: The script builds the frontend (`npm run build` in the `frontend/`
      directory).
      -- verified by: `grep -q 'npm run build' scripts/start.sh && echo OK`

- C7: The script installs backend dependencies (`uv sync` in the `backend/`
      directory).
      -- verified by: `grep -q 'uv sync' scripts/start.sh && echo OK`

- C8: The script starts uvicorn with `app.main:app`, `--host 0.0.0.0`, and
      `--port` referencing `DATABRICKS_APP_PORT` (not a hardcoded port number).
      -- verified by: `grep -qE 'uvicorn\s+app\.main:app' scripts/start.sh && grep -q '\-\-host 0.0.0.0' scripts/start.sh && grep -q 'DATABRICKS_APP_PORT' scripts/start.sh && echo OK`

- C9: The script uses `exec` for the final uvicorn command so the server
      replaces the shell process.
      -- verified by: `grep -qE 'exec .+uvicorn' scripts/start.sh && echo OK`

- C10: Reject -- `app.yaml` does not contain any hardcoded secrets, passwords,
       or connection strings.
       -- verified by: `! grep -qiE '(password|secret|postgres://|DATABASE_URL)' app.yaml && echo OK`

- C11: Reject -- `scripts/start.sh` does not contain any hardcoded port numbers
       for the server listen port (the port must come from `DATABRICKS_APP_PORT`).
       -- verified by: `! grep -qE '\-\-port [0-9]+' scripts/start.sh && echo OK`

- C12: `app.yaml` contains no `env` block (environment variables are managed in
       the Databricks App UI, not in the committed config file).
       -- verified by: `python3 -c "import yaml; d=yaml.safe_load(open('app.yaml')); assert 'env' not in d, 'env block found'; print('OK')"`

## Notes

- The Databricks Apps runtime provides Python, Node.js, and `uv` in the
  execution environment. The script does not need to install these tools.

- `DATABRICKS_APP_PORT` is set automatically by the Databricks runtime. The
  script must not set or override it.

- Standing rubric criteria S2/S3/S4 (migration-related) do not apply to this
  item since no database changes are made. S5 (API types in sync) also does not
  apply since no new API routes are added. S6 (test-only routes) is unaffected.
  S9 (contract tests frozen) applies but trivially -- no contract tests exist
  for this item.

- The `frontend/dist/` directory is gitignored. The build step in the startup
  script is what produces it at deploy time.

- The backend entry point is `backend/app/main.py` and the FastAPI object is
  named `app`. The uvicorn import path when running from within `backend/` is
  `app.main:app`.
