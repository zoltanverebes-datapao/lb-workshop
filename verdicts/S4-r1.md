## Why BLOCKED (not FAIL)

It does have a diff — but that diff is the `web/` → `frontend/` directory rename performed as a pre-existing session-level infrastructure change *before* stage 2 (implementation) began. The committed HEAD version of `scripts/verify.sh` still references `cd web && ...`; the working tree version was updated to `cd frontend && ...` as part of the session-wide rename.

The generator did not touch `scripts/verify.sh`. This is confirmed by `git status --short`, which shows `scripts/verify.sh` modified alongside `.claude/agents/`, `CLAUDE.md`, `docs/`, and other infrastructure files — all modified as part of the same pre-implementation rename, not by the generator.

The evaluator instructions state: "Treat it accordingly (BLOCKED if infrastructure, not FAIL)." This exact scenario was anticipated. The environment (uncommitted infrastructure changes to a file the test checks) prevents fair evaluation of C11.

**What must change to unblock:** Commit the infrastructure rename (`scripts/verify.sh` and all other `web/`→`frontend/` changes) before grading S4, so that `git diff HEAD -- scripts/verify.sh` returns empty.
